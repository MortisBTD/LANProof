# LANProof

Open-source Network Diagnostics & Troubleshooting

Концепция проекта v1.0

LANProof — бесплатная программа с открытым исходным кодом для Windows и Android, которая автоматически диагностирует домашнюю сеть, фиксирует обрывы, высокий пинг, потерю пакетов и помогает определить наиболее вероятный источник проблемы.

Главная идея: программа должна не просто показывать, что интернет работает плохо, а объяснять, где именно возникает неисправность и чем это подтверждается.

Обычные сетевые мониторы показывают задержку, графики и потерю пакетов. LANProof пойдёт дальше — будет сопоставлять результаты проверок с нескольких устройств, анализировать события и составлять понятный отчёт.

## 1. Какую проблему решает LANProof

Представим обычную ситуацию.

Человек играет в онлайн-игру. Внезапно пинг подскакивает с 30 до 500 мс. Через несколько секунд игра теряет соединение.

При этом Windows продолжает показывать, что компьютер подключён к Wi-Fi.

Непонятно, что произошло: перегрузился роутер, возникли помехи Wi-Fi, кто-то скачивает большой файл, произошёл сбой DNS или проблема у провайдера.

Пользователь перезагружает роутер, меняет DNS, переустанавливает драйвер и пробует другие случайные решения.

LANProof предназначен для замены такого подхода на измерения и проверяемые выводы.

## 2. Как работает программа

Схема диагностики сети

Устройства выполняют тесты со своей стороны. Центральное приложение сравнивает их результаты во времени.

После установки программа начинает одновременно проверять несколько уровней сетевого соединения.

| Уровень              | Что проверяется                                        |
| -------------------- | ------------------------------------------------------ |
| 1. Устройство        | Состояние сетевого адаптера, подключение, Wi-Fi-сигнал |
| 2. Домашняя сеть     | Связь с роутером, задержка, потеря пакетов             |
| 3. Выход в интернет  | Доступность внешних IP-адресов                         |
| 4. DNS               | Скорость и успешность разрешения доменных имён         |
| 5. Сервисы           | Доступность выбранных сайтов и игровых серверов        |
| 6. Другие устройства | Возникает ли проблема одновременно на ПК и телефоне    |

LANProof собирает результаты в общую временную шкалу.

Например, когда связь на телефоне пропадает, но подключённый кабелем компьютер продолжает нормально работать, это указывает на проблему в беспроводном сегменте или конкретном устройстве.

Если соединение со шлюзом стабильно на обоих устройствах, а внешние адреса перестают отвечать одновременно, подозрение смещается на WAN-соединение или сеть провайдера.

Важно, что это диагностические гипотезы, а не гарантированное определение виновника. Для окончательного вывода могут потребоваться дополнительные проверки.

## 3. Главная особенность — интеллектуальный анализ без обязательного ИИ

Программа должна сама обнаруживать закономерности в измерениях.

Пример события

Нестабильная сеть

Компьютер • Ethernet

Стабильно

Шлюз отвечает

Телефон • Wi-Fi

Сбой

Потеря связи со шлюзом

Предварительный диагноз

Вероятная проблема в Wi-Fi или телефоне.

Проводное соединение остаётся рабочим, а телефон теряет доступ к домашнему шлюзу. Для уточнения причины рекомендуется проверить уровень сигнала, диапазон Wi-Fi и загруженность радиоканала.

Демонстрационные данные, не реальные измерения.

Для реализации такого анализа не нужна нейросеть. Достаточно грамотно спроектированного диагностического движка, состояний сети, правил корреляции и оценки достоверности.

Это делает LANProof полностью работоспособным офлайн в локальной сети, без платных API и подписок.

## 4. Что увидит пользователь

Главное окно будет содержать четыре основных экрана.

Dashboard — мониторинг

Общий статус интернета, текущий пинг, джиттер, потеря пакетов, состояние шлюза и подключённых устройств. Все изменения отображаются в реальном времени.

Timeline — история событий

Интерактивный график за последние часы, дни или недели. Можно выделить любой момент и посмотреть, что происходило на каждом уровне сети.

Diagnostics — поиск неисправностей

Результаты автоматических проверок, вероятные причины проблем, подтверждающие измерения и рекомендации по дальнейшей проверке.

Reports — отчёты

Экспорт истории в PDF или JSON/CSV. Отчёт можно приложить к обращению в поддержку провайдера или к сообщению о проблемах игрового соединения.

## 5. Дополнительные возможности

После основного релиза проект можно расширять.

| Функция               | Назначение                                                 |
| --------------------- | ---------------------------------------------------------- |
| Game Mode             | Мониторинг соединения во время игровых сессий              |
| Bufferbloat Test      | Проверка роста задержки при загрузке сети                  |
| Wi-Fi Analyzer        | Оценка сигнала, диапазона и изменений качества подключения |
| Network Map           | Отображение известных устройств домашней сети              |
| Background Monitoring | Запись событий без постоянно открытого окна                |
| Alert System          | Уведомления о потере соединения и восстановлении           |
| Portable Mode         | Возможность запуска Windows-программы без установки        |

Отдельно я бы сделал режим мониторинга игры. Он не вмешивается в игровой процесс, а связывает временные отметки сетевых проблем с игровой сессией.

Так можно проверить, совпадают ли скачки пинга в игре с нестабильностью домашней сети. Если дома всё стабильно, проблема может быть дальше по маршруту, на стороне игрового сервиса или в самом приложении.

## 6. Техническая архитектура

Я бы выбрал следующий стек:

| Компонент               | Технология                               |
| ----------------------- | ---------------------------------------- |
| Windows-приложение      | C# / .NET + Avalonia UI                  |
| Android-приложение      | Kotlin + Jetpack Compose                 |
| Диагностический движок  | C# на Windows, Kotlin на Android         |
| Хранилище               | SQLite                                   |
| Локальная синхронизация | Защищённое соединение между устройствами |
| Графики                 | Библиотека интерактивной визуализации    |
| Форматы экспорта        | JSON, CSV, PDF                           |
| Лицензия                | MIT или Apache-2.0                       |

Архитектуру лучше разделить на независимые модули: сбор измерений, хранение результатов, движок диагностики, синхронизация устройств и интерфейс.

Это позволит позже добавить поддержку Linux, не переписывая весь проект.

При этом Android должен сохранять результаты локально и синхронизировать их после восстановления Wi-Fi. Иначе мы потеряем именно те события, ради которых создаётся программа.

Для безопасности LANProof не должен перехватывать содержимое пользовательского трафика. Все диагностические данные остаются на устройствах, если пользователь сам не экспортирует их.

### Что принципиально отличит проект от обычного пинг-монитора

Самая важная функция — корреляция измерений нескольких устройств с автоматическим объяснением событий.

Не десятки разноцветных графиков, в которых пользователь должен разбираться самостоятельно, а конкретный ответ:

«На обоих устройствах связь с роутером сохранялась. Однако внешние соединения прервались одновременно на 12 секунд. Вероятная область проблемы — подключение роутера к интернету».

Причём такой вывод должен сопровождаться данными, чтобы пользователь мог его проверить.

Предлагаемое название и оформление. Доступность имени репозитория нужно проверить перед созданием.

Проект будет ориентирован на обычных пользователей, геймеров, домашних системных администраторов и людей, которые хотят самостоятельно разобраться с нестабильным подключением.

Главная цель LANProof — превратить непонятную проблему «у меня лагает интернет» в зафиксированное событие с измерениями, вероятными причинами и понятными следующими действиями.

Именно эту функциональность я бы сделал центром проекта. Не встроенный ИИ, не огромное количество кнопок и даже не красивый график, а способность программы объяснять происходящее лучше обычных сетевых мониторов.

Если реализовать это действительно качественно, получится самостоятельный open-source продукт с понятной ценностью. Но интерес пользователей и конкурентоспособность нужно будет проверить на работающем прототипе, а не только на концепции.
