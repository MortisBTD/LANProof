# Android-компаньон · 0.2.0-beta.1

Предварительная версия на Kotlin и Jetpack Compose, Android 8.0+ (API 26), target SDK 35.

## Подключение

1. Скачайте Windows ZIP и Android APK одной версии из [Releases](https://github.com/MortisBTD/LANProof/releases). APK подписан отладочным ключом для тестирования; Google Play-публикации нет.
2. На Windows откройте **«Компаньон»**, выберите IPv4 домашней сети и нажмите **«Включить приём»**.
3. Разрешите LANProof в Windows Firewall для **частной** сети. Используется TCP 13791, проброс портов на роутере не нужен.
4. Создайте QR-код, действующий пять минут. Оба устройства должны быть в одной локальной сети; гостевой Wi-Fi с изоляцией клиентов не подходит.
5. На Android нажмите **«QR-код»**, отсканируйте экран ПК и нажмите **«Подключить»**. Можно вставить текстовый код вручную. Подтвердите телефон на Windows.
6. Нажмите **«Начать запись»** на телефоне. Android показывает постоянное уведомление с кнопкой остановки. Для синхронизации Windows-приложение должно быть открыто, а приём включён.

QR содержит одноразовый секрет. Не публикуйте его скриншоты. Отзыв доступа находится на экране компаньона Windows.

## Измерения и очередь

- Каждые пять секунд: состояние Wi-Fi, ICMP шлюза и 1.1.1.1, DNS example.com, HTTPS-заголовки google.com/generate_204.
- Сокеты, DNS и HTTPS привязаны к Wi-Fi; ICMP — к его интерфейсу. Мобильная сеть не подменяет домашнюю.
- Root не требуется. Если прошивка запрещает ping, результат ICMP **неопределённый**, а не стопроцентная потеря.
- Цикл сначала сохраняется в SQLite. После восстановления связи очередь отправляется пакетами, ПК подтверждает их после транзакции. Повторы не создают дубликаты.
- Лимит — 100 000 неотправленных циклов: при заполнении запись останавливается с сообщением. Подтверждённая история телефона хранится до семи дней. Перед очисткой очередь согласуется с часами ПК. Циклы старше 29 дней или с невосстановимым временем вне допустимого окна удаляются с сообщением: ПК принимает историю за 30 дней и до пяти минут в будущем.
- До 90 циклов отправляется за проход; большая очередь уходит постепенно. Есть ручная синхронизация.
- После перезагрузки или принудительной остановки запись нужно запустить вручную. Doze и энергосбережение производителя могут ограничивать запись даже с foreground service и wake lock.

## Согласование времени

Телефон получает время ПК и оценивает погрешность через длительность защищённого обмена. Далее используется монотонное время Android. Погрешность растёт с возрастом привязки; после перезагрузки или через сутки нужна новая синхронизация. Недавние результаты до первого сопряжения можно согласовать задним числом в пределах суток того же запуска Android.

Windows сравнивает циклы на расстоянии до 2,5 с, с погрешностью каждого не более ±1 с и общим расстоянием с погрешностями до 3 с:

- Телефон потерял Wi-Fi/шлюз, ПК сохранил шлюз и внешние сервисы → вероятная проблема Wi-Fi или телефона.
- Один шлюз доступен обоим, но внешние IP и HTTPS одновременно не прошли → вероятное общее отклонение на выходе сети.

Неизвестная погрешность и пропуски не доказывают общую причину. На графике истории выбирается устройство; метрики главного экрана остаются метриками ПК. Общие выводы включены в JSON, CSV и PDF. События Android являются точечными наблюдениями; длительность обрыва по ним не восстанавливается.

## Безопасность

Приём на Windows выключен по умолчанию, привязан к выбранному RFC1918 IPv4. TLS 1.2/1.3, закрепление SHA-256 сертификата из QR, отдельный случайный 256-битный токен и подтверждение нового телефона. На Windows секреты защищены DPAPI текущего пользователя; на Android — AES-GCM с ключом Android Keystore. Резервное копирование и перенос Android-данных отключены. Облака и входящего Android-сервера нет.

Формат, лимиты и границы доверия — в [COMPANION-PROTOCOL.md](COMPANION-PROTOCOL.md). Независимого аудита безопасности пока не было.

## Сборка и проверки

Нужны JDK 17, Android SDK platform 35 / build-tools 35.0.0 и .NET SDK 8 для межъязыкового теста.

```powershell
$env:JAVA_HOME='путь-к-JDK-17'
$env:ANDROID_HOME='путь-к-Android-Sdk'
.\tools\build-android.ps1 -Interop
```

Либо откройте `android/` в Android Studio. Обычная проверка: `gradlew -p android :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`.

Без запущенного .NET peer межъязыковой тест пропускается. Скрипт с `-Interop` поднимает его на loopback. Автоматическое подтверждение существует только в тестовом harness, не в обычном Windows-приложении.

Robolectric проверяет SQLite, часы, ICMP-парсер, формат протокола, интерфейс и обе темы. Отдельный тест соединяет настоящий Kotlin TLS-транспорт с .NET TLS-сервером и повторяет пакет очереди. Это **не** проверка реального Wi-Fi-модуля, QR-камеры, Android Keystore на устройстве или поведения конкретного производителя при выключенном экране. Физический телефон для этого этапа не использовался.
